# X-радар

Локальная система чтения X/Twitter: собирает посты из тематических списков, хранит JSONL с дедупликацией, готовит фактпак и помогает агенту написать недельный разбор, план и семь постов для Telegram. Тема по умолчанию — AI-агенты и рабочие инструменты; списки, треки и контекст можно заменить.

Это набор скриптов и промптов. Планировщик, браузер и языковую модель предоставляет ваша среда агента. Скрипты сами не запускают сбор по расписанию и не публикуют материалы.

```text
X-списки → collector.js → export.js → pull.sh → ingest.py
                                                   ↓
                                            data/posts.jsonl
                                                   ↓
                              topics.py dump/write (или опциональный auto)
                                                   ↓
                          weekly.py → фактпак → агент → дайджест и сигналы
                                                   ↓
                                   план недели + 7 черновиков Telegram
                                                   ↓
                       tg-news-stories → видео по отдельному запросу
```

## Сетка недели

| День | Код | Тема |
|---|---|---|
| Пн | MODELS | Модели и исследования |
| Вт | CODE | Кодинг-агенты |
| Ср | BUILD | Как строят агентов |
| Чт | TRUST | Доверие и качество |
| Пт | WORK | Агенты в работе |
| Сб | BIZ | Продукт и бизнес |
| Вс | WATCH | Доклады, интервью и итоги |

`NOISE` — шум, который исключают из выпусков. Списки отвечают за выбор людей, треки — за содержание: автор из списка памяти может написать о ценах. Настройка треков единая для скрипта и промптов — `tracks.json`.

## Установка

1. Клонируйте репозиторий. Для основных скриптов нужны Python 3.10+ и Bash; сторонних Python-пакетов у ядра нет. Проверено на macOS, блокировка приёма использует `fcntl` (macOS/Linux).

   ```bash
   git clone https://github.com/artkruglov/x-radar.git
   cd x-radar
   cp config.example.json config.json
   cp lists.example.json lists.json
   cp roster.example.json roster.json
   cp tracks.example.json tracks.json
   ```

2. Создайте свои X-списки и заполните их авторами из [PEOPLE.md](PEOPLE.md) или своей ниши. В `lists.json` впишите id из адресов `https://x.com/i/lists/<id>`, владельца и при необходимости аккаунт-читатель. Пустые id в примере намеренны; реальные значения в код не вписываются. `n` — локальный номер списка, `key` — его нейтральное имя. Ростер — исторический стартовый набор, перед использованием сверьте профили.

3. В `config.json` укажите пути, название и ссылку канала, аудиторию и задачи в `project_context`, часовой пояс и желаемое время. Относительные пути считаются от файла конфигурации. По умолчанию используется корневой `config.json`; другой файл выбирается через `--config` или `XRADAR_CONFIG`.

4. Войдите в X вручную в браузере вашей агентной среды. Сборщик зависит от DOM X, включая английские подписи метрик. Он требует среду, которая разрешает выполнение page JavaScript; ограниченные браузерные инструменты могут не поддерживать этот способ. Не обходите ограничения среды. Сбор неполный: прокрутка имеет бюджет времени, X может менять разметку. Повторный сбор и дедупликация помогают добирать пропуски.

5. Создайте задачи в своём планировщике по [ежедневному промпту](prompts/daily-collect.md) и [промпту понедельника](prompts/monday-weekly.md). Рекомендуемый образец — сбор в 08:00, 14:00 и 20:00, разбор по понедельникам в 09:00 в выбранном часовом поясе. Это значения шаблона; репозиторий не устанавливает фоновые процессы. Сначала выполните каждый промпт вручную и проверьте доступ к папке и браузеру.

6. Разметку можно делать самим агентом: `topics.py dump` → JSON-метки → `topics.py write`. Внешний API не нужен. Опциональный `auto` требует переменной окружения `OPENROUTER_API_KEY` и выбранного `classification.model` в конфигурации. Он передаёт тексты постов провайдеру; модели и тарифы выбирайте в своём аккаунте. `.env.example` — справочник переменных; скрипты не загружают `.env` автоматически. Значения можно экспортировать из локального файла: `set -a; source .env; set +a`.

## Проверка на вымышленном примере — без сети и ключей

Восемь постов в `examples/posts.jsonl`, аккаунты, ссылки и события вымышлены. Семь относятся к текущему окну, один — к предыдущему. Дата фиксирована, чтобы пример работал и через год. Команды выполняются из корня:

```bash
python3 radar/ingest.py --config examples/config.json < examples/posts.jsonl
python3 radar/ingest.py --config examples/config.json < examples/posts.jsonl
python3 radar/weekly.py 7 --config examples/config.json --now 2026-10-27T00:00:00Z
python3 radar/weekly.py 7 --config examples/config.json --now 2026-10-27T00:00:00Z --json
python3 radar/topics.py dump --config examples/config.json
python3 radar/topics.py write --config examples/config.json < examples/labels.json
python3 radar/topics.py stats --config examples/config.json --from 2026-10-20 --to 2026-10-26
python3 radar/topics.py pick --config examples/config.json --track WORK --full
python3 skills/tg-news-stories/scripts/radar_scan.py examples/posts.jsonl --from 2026-10-20 --to 2026-10-26 --lists-file examples/lists.json --lists 7,10 --full
```

На чистой папке первый приём даёт `new=8`, второй — `new=0 dup=8`. Повторный запуск после предыдущего демо тоже даст дубли. В фактпаке — семь постов текущего и один предыдущего периода. Данные демо пишутся только в игнорируемую `data/demo/`. Готовые образцы вывода: [фактпак](examples/factpack.md) и [JSON](examples/factpack.json).

Набор проверок ядра: `python3 -m unittest discover -s tests -v`. Он использует временные папки и не читает вашу базу. DOM-сборщик отдельно проверяется на искусственной странице: `node tests/collector.cjs`. Внешние сервисы эти проверки не вызывают.

## Ручные команды

```bash
# JSONL или JSON-массив → база
python3 radar/ingest.py < new_posts.jsonl
# base64 или результат браузерного инструмента → база
bash radar/pull.sh collector-export.txt
# Принимается также base64 со stdin
base64 < new_posts.jsonl | bash radar/pull.sh
# Фактпак без интерпретации
python3 radar/weekly.py 7
# Разметка агентом и выбор новостей
python3 radar/topics.py dump --from YYYY-MM-DD
python3 radar/topics.py write < labels.json
python3 radar/topics.py stats --from YYYY-MM-DD --to YYYY-MM-DD
python3 radar/topics.py pick --track CODE --from YYYY-MM-DD --full
```

`ingest.py` сначала проверяет весь вход, затем принимает только новые id под файловой блокировкой. Повторные наблюдения одного id не обновляют метрики или принадлежность к нескольким спискам: в базе остаётся первая версия. Пустой вход не создаёт постов. Повреждённый JSON не пропускается молча. `pull.sh` не удаляет исходный экспорт при ошибке.

`weekly.py` считает объём, вовлечённость (`likes + 3×reposts + 2×replies`), упоминания, цитаты, новых авторов, термины и молчание ростера. Частотность слов — грубая англоязычная эвристика, а не доказательство тренда. Автор вне ростера считается вероятным усилением участника списка; это эвристика, метка в исходной базе не меняется. Еженедельный промпт требует отдельно оценивать число независимых источников и качество доказательств.

## Видео и музыка

[Навык tg-news-stories](skills/tg-news-stories/SKILL.md) содержит скрипты, редакционную политику и обезличенный Remotion-шаблон. Создавайте отдельную папку выпуска через `scripts/new_episode.sh`, меняйте `brand.json`, сценарий и сцены. Для видео нужны Node 18+, ffmpeg/ffprobe, Python с Pillow, Chromium и доступ к выбранным моделям. Зависимости видео и исторические идентификаторы моделей могут потребовать обновления у вашего провайдера.

Музыки в репозитории нет. Если `audio/music/bgm.mp3` отсутствует, `mix.py` собирает только озвучку. Необязательная команда создаёт локальный тихий синтетический фон, не скачивая чужую запись (из папки выпуска):

```bash
mkdir -p audio/music
ffmpeg -f lavfi -i 'sine=frequency=110:sample_rate=48000:duration=180' -af 'volume=0.015,afade=t=in:d=2,afade=t=out:st=177:d=3' -ac 2 audio/music/bgm.mp3
```

Ролик и текст сначала просматривает пользователь; публикация в Telegram требует отдельного согласия на конкретный выпуск.

## Как адаптировать под свою тему

Меняйте три слоя: людей в X-списках и `roster.json`, справочник `tracks.json`, контекст и требования к доказательствам в конфигурации и промптах. Идентификаторы ваших списков остаются в локальном `lists.json`.

| Тема | Кого включить | Возможные треки | Что поменять в промптах |
|---|---|---|---|
| Финтех | основатели платёжных продуктов, инженеры, авторы исследований | платежи, кредитование, антифрод, инфраструктура, регуляторика, экономика, доклады | отделять продуктовые анонсы от трактовки закона; требования сверять с первоисточником |
| Геймдев | разработчики движков, студии, издатели, технические художники | движки, инструменты, производство, графика, дистрибуция, бизнес, выступления | отличать прототипы от релизов, уточнять платформу и условия сравнения |
| Биотех | исследователи, лаборатории, основатели, авторы обзоров | исследования, методы, данные, воспроизводимость, клиника, рынок, конференции | указывать стадию исследования, ограничения и публикацию; не превращать новости в медицинские советы |

Сохраняйте `NOISE` для исключений. Выбирайте устойчивые коды; переименование кода требует миграции старых меток, а смена отображаемого названия — нет. Промпты не должны заранее обещать четыре новости, если данных мало.

## Что не вошло

Реальная база и метки, логи, внутренние аналитические материалы, личные пути и аккаунт-читатель, id списков, настройки канала, переписка, готовые посты и ролики, иллюстрации, QR-коды, файлы шрифтов, голос и музыка. Публичные шаблоны расписаний адаптированы: ежедневный — из обновлённого рабочего сбора; понедельничный — из прежнего дайджеста и новой схемы треков. Это не экспорт приватных задач планировщика.

## Проверки и ограничения публикации

Результаты выполненных проверок записаны в [VALIDATION.md](VALIDATION.md). Проверяются приём, дедупликация, повреждённый вход, декодирование, период фактпака и тематические метки. Искусственная DOM-проверка не подтверждает работу с текущей разметкой X.

Живой сбор в X, модели для авторазметки/голоса/изображений, полный рендер нового ролика и отправка в Telegram при подготовке репозитория не запускались. Доступ к аккаунтам и платным сервисам проверяется пользователем в своей среде. Публикация репозитория не означает, что эти интеграции проверены.

Перед отправкой изменений запускайте gitleaks и проверяйте игнорируемые файлы; [CONTRIBUTING.md](CONTRIBUTING.md) описывает порядок. Названия переменных окружения в документации и коде — допустимые совпадения при поиске по словам, значений ключей в примерах нет.
